# ToDoList 数据库设计文档

## 概述

本文档详细描述了 ToDoList 系统的数据库设计，包括数据库结构、表结构、字段说明、索引设计、关系设计以及性能优化策略。

## 数据库信息

- **数据库类型**: MySQL
- **数据库版本**: MySQL 8.0+
- **字符集**: utf8mb4
- **排序规则**: utf8mb4_unicode_ci
- **时区**: UTC

## 表结构设计

### 1. 用户表 (user)

存储系统用户的基本信息和认证数据。

#### 表定义

```sql
CREATE TABLE `user` (
  `id` int NOT NULL AUTO_INCREMENT COMMENT '用户ID，主键',
  `username` varchar(50) NOT NULL COMMENT '用户名，唯一',
  `email` varchar(100) NOT NULL COMMENT '邮箱地址，唯一',
  `password` varchar(255) NOT NULL COMMENT '密码（bcrypt加密）',
  `role` enum('admin','user','guest') NOT NULL DEFAULT 'user' COMMENT '用户角色',
  `isActive` tinyint(1) NOT NULL DEFAULT '1' COMMENT '是否激活',
  `createdAt` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updatedAt` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `UK_username` (`username`),
  UNIQUE KEY `UK_email` (`email`),
  KEY `IDX_role` (`role`),
  KEY `IDX_isActive` (`isActive`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';
```

#### 字段说明

| 字段名 | 类型 | 长度 | 允许NULL | 默认值 | 约束 | 说明 |
|--------|------|------|---------|--------|------|------|
| id | int | - | NO | - | PK, AUTO_INCREMENT | 用户ID，主键 |
| username | varchar | 50 | NO | - | UK | 用户名，唯一索引 |
| email | varchar | 100 | NO | - | UK | 邮箱地址，唯一索引 |
| password | varchar | 255 | NO | - | - | 密码（bcrypt加密） |
| role | enum | - | NO | 'user' | - | 用户角色：admin/user/guest |
| isActive | tinyint | 1 | NO | 1 | - | 是否激活：1-激活，0-禁用 |
| createdAt | datetime | - | NO | CURRENT_TIMESTAMP | - | 创建时间 |
| updatedAt | datetime | - | NO | CURRENT_TIMESTAMP | - | 更新时间，自动更新 |

#### 索引设计

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| PRIMARY | 主键 | id | 主键索引 |
| UK_username | 唯一 | username | 用户名唯一索引 |
| UK_email | 唯一 | email | 邮箱唯一索引 |
| IDX_role | 普通 | role | 角色索引，用于权限查询 |
| IDX_isActive | 普通 | isActive | 状态索引，用于用户筛选 |

#### 数据示例

```sql

('john_doe', 'john@example.com', '$2b$10$...', 'user', 1),
```

### 2. 待办事项表 (todo)

存储用户的待办事项信息。

#### 表定义

```sql
CREATE TABLE `todo` (
  `id` int NOT NULL AUTO_INCREMENT COMMENT '待办事项ID，主键',
  `title` varchar(200) NOT NULL COMMENT '待办事项标题',
  `description` text COMMENT '待办事项描述',
  `completed` tinyint(1) NOT NULL DEFAULT '0' COMMENT '是否完成',
  `status` enum('pending','in_progress','completed') NOT NULL DEFAULT 'pending' COMMENT '状态',
  `completedAt` datetime DEFAULT NULL COMMENT '完成时间',
  `priority` enum('low','medium','high') NOT NULL DEFAULT 'medium' COMMENT '优先级',
  `dueDate` date DEFAULT NULL COMMENT '截止日期',
  `userId` int NOT NULL COMMENT '用户ID，外键',
  `createdAt` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updatedAt` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `IDX_userId` (`userId`),
  KEY `IDX_status` (`status`),
  KEY `IDX_priority` (`priority`),
  KEY `IDX_dueDate` (`dueDate`),
  KEY `IDX_userId_status` (`userId`, `status`),
  CONSTRAINT `FK_todo_user` FOREIGN KEY (`userId`) REFERENCES `user` (`id`) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='待办事项表';
```

#### 字段说明

| 字段名 | 类型 | 长度 | 允许NULL | 默认值 | 约束 | 说明 |
|--------|------|------|---------|--------|------|------|
| id | int | - | NO | - | PK, AUTO_INCREMENT | 待办事项ID，主键 |
| title | varchar | 200 | NO | - | - | 待办事项标题 |
| description | text | - | YES | NULL | - | 待办事项描述 |
| completed | tinyint | 1 | NO | 0 | - | 是否完成：1-完成，0-未完成 |
| status | enum | - | NO | 'pending' | - | 状态：pending/in_progress/completed |
| completedAt | datetime | - | YES | NULL | - | 完成时间 |
| priority | enum | - | NO | 'medium' | - | 优先级：low/medium/high |
| dueDate | date | - | YES | NULL | - | 截止日期 |
| userId | int | - | NO | - | FK | 用户ID，外键关联user表 |
| createdAt | datetime | - | NO | CURRENT_TIMESTAMP | - | 创建时间 |
| updatedAt | datetime | - | NO | CURRENT_TIMESTAMP | - | 更新时间，自动更新 |

#### 索引设计

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| PRIMARY | 主键 | id | 主键索引 |
| IDX_userId | 普通 | userId | 用户ID索引，用于关联查询 |
| IDX_status | 普通 | status | 状态索引，用于状态筛选 |
| IDX_priority | 普通 | priority | 优先级索引，用于优先级排序 |
| IDX_dueDate | 普通 | dueDate | 截止日期索引，用于日期查询 |
| IDX_userId_status | 复合 | userId, status | 用户+状态复合索引，优化用户待办事项查询 |
| FK_todo_user | 外键 | userId | 外键约束，关联user表 |

#### 外键约束

| 约束名 | 字段 | 引用表 | 引用字段 | 删除规则 | 更新规则 |
|--------|------|--------|---------|---------|---------|
| FK_todo_user | userId | user | id | CASCADE | CASCADE |

#### 数据示例


## 关系设计

### 用户-待办事项关系

**关系类型**: 一对多 (1:N)

**说明**:
- 一个用户可以拥有多个待办事项
- 一个待办事项只能属于一个用户
- 当用户被删除时，关联的待办事项也会被级联删除（CASCADE）

**关系图**:
```
User (1) ──────── (N) Todo
```

**查询示例**:

```sql
-- 查询用户及其所有待办事项
SELECT u.*, t.* 
FROM user u
LEFT JOIN todo t ON u.id = t.userId
WHERE u.id = 1;

-- 查询用户的待办事项统计
SELECT 
  u.id,
  u.username,
  COUNT(t.id) as totalTodos,
  SUM(CASE WHEN t.status = 'pending' THEN 1 ELSE 0 END) as pendingTodos,
  SUM(CASE WHEN t.status = 'in_progress' THEN 1 ELSE 0 END) as inProgressTodos,
  SUM(CASE WHEN t.status = 'completed' THEN 1 ELSE 0 END) as completedTodos
FROM user u
LEFT JOIN todo t ON u.id = t.userId
GROUP BY u.id, u.username;
```

## 性能优化策略

### 1. 索引优化

- **主键索引**: 所有表都使用自增主键，提高插入性能
- **唯一索引**: 用户名和邮箱使用唯一索引，确保数据唯一性
- **复合索引**: 待办事项表使用 `userId + status` 复合索引，优化用户待办事项查询
- **覆盖索引**: 常用查询字段建立索引，减少回表操作

### 2. 查询优化

```sql
-- 使用索引覆盖查询
SELECT id, title, status, priority, dueDate 
FROM todo 
WHERE userId = ? AND status = ?;

-- 避免使用 SELECT *
SELECT id, title, status 
FROM todo 
WHERE userId = ?;

-- 使用 LIMIT 分页
SELECT * 
FROM todo 
WHERE userId = ? 
ORDER BY createdAt DESC 
LIMIT 10 OFFSET 0;
```

### 3. 数据类型优化

- **整数类型**: 使用合适的整数类型（TINYINT, INT）节省存储空间
- **字符串类型**: 根据实际需求选择 VARCHAR 长度
- **枚举类型**: 使用 ENUM 存储固定值，节省空间并提高查询效率
- **时间类型**: 使用 DATETIME 存储精确时间，使用 DATE 存储日期

### 4. 分区策略（可选）

对于大规模数据，可以考虑按时间分区：

```sql
-- 按创建时间分区
ALTER TABLE todo 
PARTITION BY RANGE (YEAR(createdAt)) (
  PARTITION p2023 VALUES LESS THAN (2024),
  PARTITION p2024 VALUES LESS THAN (2025),
  PARTITION p2025 VALUES LESS THAN (2026),
  PARTITION pmax VALUES LESS THAN MAXVALUE
);
```

## 数据迁移

### 初始化脚本

```sql
-- 创建数据库
CREATE DATABASE IF NOT EXISTS todolist 
CHARACTER SET utf8mb4 
COLLATE utf8mb4_unicode_ci;

USE todolist;

-- 创建用户表
CREATE TABLE `user` (
  `id` int NOT NULL AUTO_INCREMENT,
  `username` varchar(50) NOT NULL,
  `email` varchar(100) NOT NULL,
  `password` varchar(255) NOT NULL,
  `role` enum('admin','user','guest') NOT NULL DEFAULT 'user',
  `isActive` tinyint(1) NOT NULL DEFAULT '1',
  `createdAt` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updatedAt` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `UK_username` (`username`),
  UNIQUE KEY `UK_email` (`email`),
  KEY `IDX_role` (`role`),
  KEY `IDX_isActive` (`isActive`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 创建待办事项表
CREATE TABLE `todo` (
  `id` int NOT NULL AUTO_INCREMENT,
  `title` varchar(200) NOT NULL,
  `description` text,
  `completed` tinyint(1) NOT NULL DEFAULT '0',
  `status` enum('pending','in_progress','completed') NOT NULL DEFAULT 'pending',
  `completedAt` datetime DEFAULT NULL,
  `priority` enum('low','medium','high') NOT NULL DEFAULT 'medium',
  `dueDate` date DEFAULT NULL,
  `userId` int NOT NULL,
  `createdAt` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updatedAt` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `IDX_userId` (`userId`),
  KEY `IDX_status` (`status`),

  KEY `IDX_dueDate` (`dueDate`),
```

## 安全考虑

### 1. 密码安全

- 使用 bcrypt 加密存储密码
- 密码字段长度为 255，支持 bcrypt 哈希值
- 建议使用 bcrypt cost factor >= 10

### 2. SQL 注入防护

- 使用参数化查询
- 使用 TypeORM 的查询构建器或 Repository 模式
- 避免直接拼接 SQL 语句

### 3. 数据访问控制

- 应用层实现基于角色的访问控制（RBAC）
- 数据库层使用外键约束保证数据完整性
- 敏感字段（如密码）不在 API 响应中返回

### 4. 审计日志

- 记录关键操作的审计日志
- 包含操作人、操作时间、操作内容等信息
