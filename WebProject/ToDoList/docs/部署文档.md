# ToDoList 部署文档

## 概述

本文档详细描述了 ToDoList 系统的部署流程，包括开发环境、测试环境和生产环境的部署方案，以及相关的配置说明和运维指南。

## 部署架构

### 整体架构图

```
┌─────────────────────────────────────────────────────────┐
│                    负载均衡器 (Nginx)                     │
└────────────────────┬────────────────────────────────────┘
                     │
        ┌────────────┴────────────┐
        │                         │
┌───────▼────────┐        ┌───────▼────────┐
│  应用服务器 1   │        │  应用服务器 2   │
│  (NestJS)      │        │  (NestJS)      │
└───────┬────────┘        └───────┬────────┘
        │                         │
        └────────────┬────────────┘
                     │
        ┌────────────▼────────────┐
        │    MySQL 主从集群        │
        │  (Master + Slaves)       │
        └─────────────────────────┘
```

### 技术栈

- **应用服务器**: Node.js 22+ / NestJS
- **数据库**: MySQL 8.0+
- **容器化**: Docker & Docker Compose
- **反向代理**: Nginx (可选)
- **进程管理**: PM2 (可选)
- **日志管理**: Winston + 日志轮转

## 环境要求

### 系统要求

- **操作系统**: Linux (Ubuntu 20.04+ / CentOS 7+) / macOS / Windows
- **内存**: 最低 2GB，推荐 4GB+
- **磁盘空间**: 最低 10GB，推荐 20GB+
- **CPU**: 最低 2核，推荐 4核+

### 软件要求

- **Docker**: 20.10+
- **Docker Compose**: 2.0+
- **Node.js**: 22+ (本地开发)
- **pnpm**: 8+ (本地开发)
- **MySQL**: 8.0+ (不使用 Docker 时)

## Docker 部署详解

### Dockerfile 说明

```dockerfile
# 基础镜像
FROM node:22-alpine AS base
WORKDIR /app

# 依赖安装阶段
FROM base AS deps
COPY package.json pnpm-lock.yaml ./
RUN corepack enable pnpm && pnpm install --frozen-lockfile

# 构建阶段
FROM base AS builder
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN corepack enable pnpm && pnpm run build

# 运行阶段
FROM base AS runner
ENV NODE_ENV=production
RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nestjs
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./
RUN chown -R nestjs:nodejs /app
USER nestjs
EXPOSE 3000
CMD ["node", "dist/main"]
```

### 多阶段构建优势

1. **减小镜像大小**: 最终镜像只包含运行时必需的文件
2. **提高安全性**: 构建工具和依赖不会出现在最终镜像中
3. **加快部署速度**: 利用 Docker 缓存层，减少重复构建时间

## 传统部署方式

### 使用 PM2 部署

#### 1. 安装依赖

```bash
cd server
pnpm install
```

#### 2. 构建应用

```bash
pnpm run build
```

#### 3. 配置 PM2

创建 `ecosystem.config.js` 文件：

```javascript
module.exports = {
  apps: [
    {
      name: 'todolist-api',
      script: './dist/main.js',
      instances: 'max',
      exec_mode: 'cluster',
      autorestart: true,
      watch: false,
      max_memory_restart: '1G',
      env: {
        NODE_ENV: 'production',
        PORT: 3000,
      },
      env_production: {
        NODE_ENV: 'production',
      },
      error_file: './logs/pm2-error.log',
      out_file: './logs/pm2-out.log',
      log_date_format: 'YYYY-MM-DD HH:mm:ss Z',
      merge_logs: true,
    },
  ],
};
```

#### 4. 启动应用

```bash
# 启动应用
pm2 start ecosystem.config.js --env production

# 查看状态
pm2 status

# 查看日志
pm2 logs todolist-api

# 重启应用
pm2 restart todolist-api

# 停止应用
pm2 stop todolist-api

# 删除应用
pm2 delete todolist-api
```

#### 5. 设置 PM2 开机自启

```bash
# 保存 PM2 进程列表
pm2 save

# 生成开机启动脚本
pm2 startup

# 执行生成的命令（根据系统不同）
sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u your_user --hp /home/your_user
```

## Nginx 反向代理配置

### 配置文件

创建 `/etc/nginx/sites-available/todolist` 文件：

```nginx
upstream todolist_backend {
    least_conn;
    server 127.0.0.1:3000;
    server 127.0.0.1:3001;
    server 127.0.0.1:3002;
}

server {
    listen 80;
    server_name api.example.com;

    # 限制请求体大小
    client_max_body_size 10M;

    # 日志配置
    access_log /var/log/nginx/todolist_access.log;
    error_log /var/log/nginx/todolist_error.log;

    # Gzip 压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css text/xml text/javascript application/json application/javascript application/xml+rss;

    # API 路由
    location / {
        proxy_pass http://todolist_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        
        # 超时配置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # 健康检查
    location /health {
        proxy_pass http://todolist_backend/health;
        access_log off;
    }
}
```

### 启用配置

```bash
# 创建软链接
sudo ln -s /etc/nginx/sites-available/todolist /etc/nginx/sites-enabled/

# 测试配置
sudo nginx -t

# 重启 Nginx
sudo systemctl restart nginx
```

## 数据库部署

### MySQL 主从复制配置

#### 主数据库配置

编辑 `/etc/mysql/mysql.conf.d/mysqld.cnf`：

```ini
[mysqld]
server-id = 1
log-bin = mysql-bin
binlog-format = ROW
binlog-do-db = todolist
```

#### 从数据库配置

编辑 `/etc/mysql/mysql.conf.d/mysqld.cnf`：

```ini
[mysqld]
server-id = 2
relay-log = mysql-relay-bin
log-bin = mysql-bin
binlog-format = ROW
read-only = 1
```

#### 配置主从复制

```sql
-- 在主数据库上执行
CREATE USER 'replication_user'@'%' IDENTIFIED BY 'replication_password';
GRANT REPLICATION SLAVE ON *.* TO 'replication_user'@'%';
FLUSH PRIVILEGES;
SHOW MASTER STATUS;

-- 在从数据库上执行
CHANGE MASTER TO
  MASTER_HOST='master_db_ip',
  MASTER_USER='replication_user',
  MASTER_PASSWORD='replication_password',
  MASTER_LOG_FILE='mysql-bin.000001',
  MASTER_LOG_POS=154;

START SLAVE;
SHOW SLAVE STATUS;
```

## 备份与恢复

### 数据库备份

```bash
# 完整备份
docker exec todolist-mysql mysqldump -u root -proot todolist > backup_$(date +%Y%m%d_%H%M%S).sql

# 仅备份结构
docker exec todolist-mysql mysqldump -u root -proot --no-data todolist > schema_backup.sql

# 仅备份数据
docker exec todolist-mysql mysqldump -u root -proot --no-create-info todolist > data_backup.sql
```

### 自动备份脚本

创建 `backup.sh` 文件：

```bash
#!/bin/bash

BACKUP_DIR="/backups"
DATE=$(date +%Y%m%d_%H%M%S)
MYSQL_CONTAINER="todolist-mysql"
DATABASE="todolist"

mkdir -p $BACKUP_DIR

docker exec $MYSQL_CONTAINER mysqldump -u root -proot $DATABASE > $BACKUP_DIR/todolist_$DATE.sql

# 保留最近 7 天的备份
find $BACKUP_DIR -name "todolist_*.sql" -mtime +7 -delete
```

设置定时任务：

```bash
# 编辑 crontab
crontab -e

# 每天凌晨 2 点执行备份
0 2 * * * /path/to/backup.sh
```

### 数据恢复

```bash
# 恢复完整备份
docker exec -i todolist-mysql mysql -u root -proot todolist < backup_20240101_020000.sql
```

## 性能优化

### 应用层优化

1. **启用集群模式**: 使用 PM2 或 Node.js cluster 模式
2. **连接池优化**: 调整数据库连接池大小
3. **缓存策略**: 使用 Redis 缓存热点数据
4. **压缩响应**: 启用 Gzip 压缩

### 数据库优化

1. **索引优化**: 为常用查询字段创建索引
2. **查询优化**: 使用 EXPLAIN 分析慢查询
3. **配置优化**: 调整 MySQL 配置参数
4. **读写分离**: 使用主从复制分担读压力

### Nginx 优化

1. **启用缓存**: 配置 Nginx 缓存
2. **压缩传输**: 启用 Gzip 压缩
3. **负载均衡**: 配置多台应用服务器
4. **限流保护**: 配置请求限流

## 安全加固

- 不要在代码中硬编码敏感信息
- 使用 `.env` 文件管理环境变量
- 确保 `.env` 文件不提交到版本控制

- 定期更新依赖包

- 定期备份数据
- 加密敏感数据
